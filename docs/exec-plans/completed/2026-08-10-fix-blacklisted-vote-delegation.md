# fix-blacklisted-vote-delegation: исключить blacklist из делегированных голосов

## Контекст
- `cmd_gen_mtl_vote_list()` сначала переносит баланс по делегациям и только затем обнуляет адреса из blacklist.
- Из-за этого заблокированный адрес может передать голосующий баланс обычному делегату до применения blacklist.
- Blacklist используется как намеренный sink: баланс должен исключаться, если заблокирован сам владелец либо любой адрес в его цепочке делегации.
- Делегация обычного адреса на заблокированный адрес также должна исключать баланс, а не возвращать владельцу право самостоятельного голоса.
- Расчёт используется одновременно генерацией vote XDR и отчётом `MTL_TopHolders`, поэтому исправление должно находиться в общей функции расчёта.

## План изменений

   - заблокированный источник делегирует обычному адресу — его баланс не прибавляется делегату;
   - обычный источник делегирует заблокированному адресу — баланс источника исключается;
   - многошаговая цепочка, содержащая заблокированный адрес, не пропускает баланс дальше;
   - цепочка без blacklist сохраняет текущее поведение;

## Риски и открытые вопросы
- Многошаговые цепочки сейчас обрабатываются максимум за три прохода; blacklist-aware обход не должен наследовать этот произвольный предел и обязан безопасно завершаться на циклах.
- Нельзя удалять исходные записи из `delegate_list`: они нужны для отображения фактических настроек аккаунтов в Google Sheets, даже если голосовой баланс исключён.
- Проверка blacklist должна сохранить текущую семантику ответа `blacklist.json`: заблокированными считаются только адреса с truthy-значением.
- Недоступная цель делегации не относится к blacklist и не должна получить новое бизнес-поведение в рамках этого фикса.
- Во время GREEN-прогона обнаружен двойной учёт `balance_delegated`: свойство `balance` уже включает его, а старый код прибавлял значение повторно. Перенос исправлен на единственное прибавление `shareholder.balance`; тест цикла подтверждает сохранение общей суммы.

## Верификация
- RED/GREEN: `uv run pytest -q tests/other/stellar/test_voting_utils.py`.
- В тестах проверить итоговые `balance`, `balance_rect` и `balance_delegated`, а не только внутренние вызовы helper-функции.
- Проверить сценарии `blacklisted -> normal`, `normal -> blacklisted`, `normal -> normal -> blacklisted`, валидную цепочку и цикл.
- Полная регрессия: `uv run ruff format --check . && just lint && just types && just test && just secrets`.
- Ожидаемый результат: ни собственный, ни делегированный баланс цепочки, затронутой blacklist, не входит в `calculated_votes`; остальные цепочки рассчитываются без изменений.
