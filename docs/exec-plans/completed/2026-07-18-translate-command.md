# translate-command: перевод сообщений через LLM

## Контекст
- Пользователям нужен быстрый перевод текста и подписей Telegram без подключения отдельного translation API.
- Согласованный интерфейс: `/tr <язык> [текст]` и `/translate <язык> [текст]`; без языка или с неизвестным кодом LLM не вызывается.
- Поддерживаемые коды: `ru`, `en`, `es`, `de`, `me`, `cnr`; `me` и `cnr` означают черногорский.
- Если inline-текста нет, источником служит `text`, затем `caption` сообщения, на которое ответили. Результат отвечает на команду.

## Риски и открытые вопросы
- Bot использует HTML parse mode, поэтому весь LLM-ответ необходимо экранировать перед отправкой.
- Длинный перевод может превысить лимит Telegram; ответ должен разбиваться безопасными частями.
- Команда может содержать суффикс имени бота (`/tr@test_bot`), который должен корректно разбираться aiogram-фильтром и нашим парсером.
- Исходный и переведённый тексты нельзя писать в runtime-логи.

## Верификация
- `/tr es hello` вызывает AI service с `hello` и целевым `Spanish`.
- `/tr en` в reply использует `reply.text`, затем `reply.caption`; inline-текст имеет приоритет.
- `/tr`, `/tr zz` и reply без текста/caption возвращают подсказку без вызова LLM.
- `me`, `cnr` и коды в верхнем регистре нормализуются корректно.
- `<`, `>` и `&` в переводе безопасно доставляются при HTML parse mode.
- Повторный вызов пользователя раньше 5 секунд блокируется существующим throttling middleware.
- Два конкурентных запроса одного пользователя из разных чатов используют общий Redis bucket; атомарно проходит ровно один.
- Финальная проверка: Ruff clean, Pyright `0 errors`, `848 passed`; code review без Critical/Important/Minor замечаний.
